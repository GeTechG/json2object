## Why

Nothing pins or checks OpenSpec here. Agents used whatever global `openspec` they found, the repository has no
OpenSpec skills (so every archived change was written by hand and none has `.openspec.yaml`), CI checks only
`commit-kinds`, and `openspec validate --all --strict` 1.16.0 fails on two main specs. `openspec/config.yaml` carries
only `context`, so artifacts get no format rules.

## What Changes

- `openspec/cli.pin` names the OpenSpec version (`1.16.0`); the machine has it installed globally, CI runs it with
  `npm exec`. AGENTS.md records the pin and the one-commit bump.
- The OpenSpec skills (propose, explore, continue, apply, update, ff, sync, archive, bulk-archive, verify) are
  generated by the pinned version for Claude Code (`.claude/skills/openspec-*`) and Codex (`.agents/skills/openspec-*`)
  and committed. `.claude/` and `.agents/` become infrastructure paths.
- A new CI job `openspec` fails on: any issue from `openspec validate --all --strict`; a main spec whose Purpose is the
  archive placeholder; an active change without `.openspec.yaml`; an OpenSpec skill whose `generatedBy` is not the pin;
  an open task in an archived change that is not `[human]`.
- `openspec/config.yaml` gains `rules.specs`, `rules.tasks` and `operations.apply` / `operations.archive` guidance that
  points at AGENTS.md instead of restating it.
- The two over-long requirements (`json-schema`, `tagged-enum`) are rewritten without loss of meaning.

## Non-goals

- The archived changes are not repaired (no `.openspec.yaml` is added to them).
- No change to the library (`src/`, `tests/`).

## Capabilities

### New Capabilities
- `openspec-gate`: the pinned OpenSpec version and what CI checks about the OpenSpec tree.

### Modified Capabilities
- `json-schema`, `tagged-enum`: one requirement each is split to meet the 500-character limit; behaviour unchanged.

## Impact

Infrastructure only: `openspec/`, `.claude/skills/`, `.agents/skills/`, `.github/workflows/ci.yml`,
`.github/infra-paths`, `AGENTS.md`. Verified by the `openspec` CI job on this branch and by
`openspec validate --all --strict` / `openspec validate --archived` locally.
