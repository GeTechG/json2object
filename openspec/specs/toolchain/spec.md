# toolchain Specification

## Purpose
Say which compiler builds this fork and give every checkout that compiler and symbol navigation with one command.

## Requirements

### Requirement: The compiler is pinned in the repository
The compiler SHALL be the build of `GeTechG/haxe` named by the tracked file `tools/haxe-build.pin`: one line, `<build key, 40 hex> <sha256 of the archive, 64 hex>`. Building, typing and testing SHALL use only this compiler (`.haxe/haxe`, `HAXE_STD_PATH=.haxe/std`).

#### Scenario: Changing the compiler
- **WHEN** another build is to be used
- **THEN** one commit changes `tools/haxe-build.pin` and nothing else has to change

#### Scenario: The archive does not match the pin
- **WHEN** the downloaded archive's sha256 differs from the pin
- **THEN** `tools/setup.sh` fails and installs nothing

### Requirement: One command prepares a checkout
`bash tools/setup.sh` SHALL, in a fresh checkout or worktree, install the pinned compiler and point the gitignored `.haxe` symlink at it, fetch the test libraries, write the test config `.haxe-tests.hxml`, configure Serena, and provide `ast-grep` with the Haxe grammar under the gitignored `.ast-grep/`. Downloads and builds SHALL live in a per-user cache shared by all checkouts, one directory per pin, and the command SHALL write only gitignored files in the checkout.

#### Scenario: Fresh worktree
- **WHEN** `bash tools/setup.sh` has run in a fresh worktree
- **THEN** `.haxe/haxe --version` reports the pinned build and `git status` shows no change

#### Scenario: Second checkout
- **WHEN** the command runs in another checkout with the same pins
- **THEN** it downloads and builds nothing

### Requirement: Serena navigates symbols with the pinned compiler
The setup command SHALL build `vshaxe/haxe-language-server` from source at a pinned commit and write `.serena/project.local.yml` so that Serena starts it with `.haxe` first in `PATH`; the server reaches the compiler over a socket. The display config SHALL hold only `-cp`, `-D` and `-w` arguments with absolute or root-relative paths, followed by every module of the source classpaths, one dotted path per line, generated by walking the directories.

#### Scenario: Finding references
- **WHEN** Serena's `find_referencing_symbols` is asked for a symbol of `src/`
- **THEN** it returns the references, and the server log contains `Using --server-connect`

#### Scenario: The display config compiles
- **WHEN** `.haxe/haxe .serena/lsp.hxml --no-output` runs after setup
- **THEN** it exits 0

#### Scenario: Foreign Serena overrides
- **WHEN** `.serena/project.local.yml` has content not generated by the setup command
- **THEN** the command fails without overwriting it

### Requirement: Reference lists are not trusted for a rename
`AGENTS.md` SHALL state that the language server's reference lists are not exhaustive, that the setup command is re-run after source files are added or removed, and that before a rename the list is checked against a text search.

#### Scenario: Rename
- **WHEN** an agent is about to rename a symbol
- **THEN** it compares Serena's references with a text search for the name

### Requirement: Code is searchable by shape
The setup command SHALL install `ast-grep` at the version pinned in `tools/setup.sh` as `.ast-grep/ast-grep`, and build the `GeTechG/tree-sitter-haxe` grammar at the commit pinned there as `.ast-grep/haxe.so`. The tracked `sgconfig.yml` at the root SHALL register that library as the language `haxe` for `*.hx` files. `AGENTS.md` SHALL say when to use `ast-grep`, when Serena and when a text search.

#### Scenario: Searching by pattern
- **WHEN** `.ast-grep/ast-grep run -p 'throw new $T($$$A)' -l haxe src` runs after setup
- **THEN** it reports every `throw new …(…)` expression of `src/`

#### Scenario: Files the grammar cannot parse
- **WHEN** `.ast-grep/ast-grep run --kind ERROR -l haxe .` reports a file
- **THEN** a structural search may miss code in that file, and the result is confirmed with a text search
